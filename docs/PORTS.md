# 端口模型：为什么你以后不需要再动路由器

一句话：**对外只需一个端口，永远那一个。** 其余全部落在 relay 的回环上。

```
                       校园网 / 公网
                            │
                            │ 只有这一个对外端口
                            ▼
                  ┌──────────────────────┐
                  │ 10.101.54.192:18322  │  ← 路由器只映射这一个到 102 的 sshd
                  └──────────┬───────────┘
                             │ 102（Linux relay）
        ┌────────────────────┼────────────────────┐
        │  127.0.0.1:13435   │  127.0.0.1:13440   │  ← 每节点一对，全部只绑回环
        │  127.0.0.1:13437   │  127.0.0.1:13441   │     路由器不需要知道它们
        └────────────────────┴────────────────────┘
             节点 A（win2）        节点 B（新机）
```

## 三个层次

| 层 | 谁在监听 | 需不需要动路由器 |
|---|---|---|
| **入口** | relay sshd `:18322` | **一个就够**（已经开好了） |
| **节点落地端口** | relay 上 `127.0.0.1:<每节点一对>` | **不需要**：只绑回环，外部根本看不到 |
| **Windows 本机** | `127.0.0.1:19022`(sshd) / `127.0.0.1:3425`(magpie) | **不需要**：Windows 完全不出站以外的暴露 |

新加一台机器时，变化只有一处：**多一对回环端口号**。路由器配置表不动。

## 能复用多少个？

瓶颈不是路由器，而是 relay 的资源：

| 限制 | 实测/典型值 | 说明 |
|---|---|---|
| 回环端口号空间 | 13440–13600（本项目预留 80 对） | 一对 = 一台节点，随时可扩到任意空闲段 |
| sshd 每连接会话数 | Debian 默认 `MaxSessions 10` | 这是**单条 TCP 连接内**的通道数，不影响节点数 |
| 并发 ssh 连接 | 默认 `MaxStartups 10:30:100` | 冷启动限流；稳定运行后每节点常驻 2 条连接 |
| 文件描述符 | `ulimit -n`（102 上通常 1024+） | 每节点约 2 个 fd，**几百个节点没问题** |
| **路由器端口** | **1** | 这才是以前每加一台就要折腾的那个东西——现在不用了 |

真要说上限：`permitlisten` 端口段用完后换一段即可；relay 端 fd 才是实际天花板（数百级）。

## bootstrap 端口（18443）：开放开户口（机主拍板：无 token，都能连）

```
新机 PowerShell 一行:
  iex((New-Object Net.WebClient).DownloadString('http://10.101.54.192:18443/i'))
```

| 要点 | 说明 |
|---|---|
| 需要的路由器规则 | 一次：外部 `18443` → `192.168.1.102:18443` |
| 身份 | 无 token、无客户端参数：按来源 IP 先记一个名字；节点装完自动 register 上报 UUID/MAC，30 分钟对账器**自动合并同 UUID 的重复槽位**（换 IP/重装不再越积越多） |
| 限速 | 每 IP 每分钟 6 次；全量进 `bootstrap.log` |
| 天花板 | 端口池 80 对用完即拒（enroll.sh 自己拒绝），AK 不会无限膨胀 |
| 风险（机主已接受） | 全校任何人可批量开户占满池子；节点 key 无权（只绑自己回环端口、无 -L、无 shell），代价是资源不是权限；发现垃圾节点 → `revoke-node.sh <名>` 逐个清 |
| 离线兜底 | USB 的 `client/onboard.cmd`（SSH 版，内嵌登记私钥）不依赖这个口 |

`/healthz` 无需参数；错误响应是合法 PowerShell（注释 + 黄色提示），`iex` 不会再爆红字。

## 为什么不把节点端口直接映射到路由器

因为那会让**每一台** Windows 的 sshd 暴露在校园网上。本方案里 Windows 的 sshd 只绑
`127.0.0.1`，外部唯一入口是 relay 的 sshd，而 relay 上的节点端口只绑回环——
**从校园网侧扫不到任何一台节点**。

## 顺带：在 relay 上看 magpie 的 web 页面（不需要开端口）

你要在 102 那台机器上做 zcode 登录，就需要它的 magpie 页面（`127.0.0.1:3430`）。
不用开新端口，用现成的 18322 做一条本地转发：

```powershell
# 在你的笔记本上（-L 把 relay 的 3430 映射到本机 3430）
ssh -N -L 3430:127.0.0.1:3430 deb-h61
```

然后浏览器打开 **http://127.0.0.1:3430**。这条连接走的还是 18322，路由器不用改。

> 同理可以映射 `3425`（网关本身）做 API 调试，或映射 `18080`（wiki）。

| `0.0.0.0:13402` / `13403` | ⚠️ **别人**（102 上一个 `ssh` 进程）把反向端口绑到了 `0.0.0.0`，对校园网可见。不是本项目的东西，但建议关掉或改绑回环 |

> 「绑回环」是本项目所有端口的一条铁律：`permitlisten="127.0.0.1:<port>"` 只放行回环绑定，
> 客户端也必须写全 `-R 127.0.0.1:<port>:...`（见 `PITFALLS.md` B1）。
